# IBM Cloud Diagram Editing with drawio-mcp-server

## Prerequisites

1. The `drawio` MCP server must be running (check Bob's MCP panel — it starts automatically
   when the workspace is open if `.bob/mcp.json` is present).
2. The generated diagram must be open in the MCP editor at `http://localhost:4000` — use
   **Option E** in the Network Picasso diagram step to push it there.
3. Call `list-documents` first to get the `target_document.id` if more than one Draw.io tab
   is connected.

---

## IBM Cloud Visual Language

### Node Pattern (IBM Prescribed Node)

Every IBM Cloud service is rendered as **two nested cells**:

| Cell | Role | Style |
|---|---|---|
| Outer (bg) | Colored square | `shape=rect; fillColor=<category-color>; strokeColor=none` |
| Inner (icon) | White icon overlay | `shape=mxgraph.ibm_cloud.<stencil-name>; fillColor=#ffffff; part=1` |

**Never use a bare stencil cell** — the label must sit below the outer cell, not on the icon.

### Location Pattern (IBM Prescribed Location)

Containers (VPC, Region, AZ) use **four nested cells**:

| Cell | Role |
|---|---|
| Outer container | `container=1; fillColor=none; strokeColor=<color>` |
| Left strip | 4px-wide `shape=rect; fillColor=<color>` |
| Icon | `shape=mxgraph.ibm_cloud.<shape>; fillColor=<color>; part=1` |
| Label | `shape=rect; fillColor=none; labelPosition=right` |

## Step-by-Step Tool Sequences

### "Add a node to a subnet band"

Example: *"Add a Bastion Host to the Management subnet in zone-1"*

1. **Read the diagram** — call `list-paged-model` with `target_page: {index: 0}` and
   `page_size: 200` to get all cell IDs. Find the Management band cell inside zone-1
   (it has `value="Management"` and is a child of the zone-1 column container).
   Note its `id` — this is your `parent_id`.

2. **Get IBM-styled XML** — call the Network Picasso API at `POST http://localhost:8787/api/drawio-snippet`:
   ```json
   {
     "kind": "node",
     "name": "Bastion Host",
     "shape": "bastion-host",
     "x": 50,
     "y": 50,
     "size": 48,
     "parentId": "<management-band-cell-id>"
   }
   ```
   The response is raw IBM-styled Draw.io XML.

3. **Inject into diagram** — call `import-diagram`:
   ```json
   {
     "target_page": { "index": 0 },
     "data": "<xml from step 2>",
     "format": "xml",
     "mode": "add"
   }
   ```

4. **Confirm** — call `list-paged-model` again to verify the new cell appears with the
   correct parent.

---

### "Add a connector between two nodes"

Example: *"Connect the Bastion Host to the ROKS cluster"*

1. Call `list-paged-model` to find the cell IDs of both nodes (the outer bg cell ID).
2. Call `add-edge`:
   ```json
   {
     "target_page": { "index": 0 },
     "source_id": "<bastion-cell-id>",
     "target_id": "<roks-cell-id>",
     "text": "SSH",
     "style": "endArrow=block;endFill=1;strokeColor=#1192E8;"
   }
   ```

---

### "Delete a node"

1. Call `list-paged-model` to find the cell ID of the node to remove.
2. Call `delete-cell-by-id`:
   ```json
   {
     "target_page": { "index": 0 },
     "cell_id": "<node-cell-id>"
   }
   ```
   Note: deleting the outer bg cell also removes the icon child.

---

### "Add a new container (VPC, subnet, AZ)"

Example: *"Add a Management subnet band to zone-2"*

1. Find the zone-2 column cell ID via `list-paged-model`.
2. Call `POST http://localhost:8787/api/drawio-snippet`:
   ```json
   {
     "kind": "location",
     "name": "Management",
     "shape": "ibm-cloud--vpc",
     "strokeColor": "#FA4D56",
     "x": 0,
     "y": 210,
     "width": 280,
     "height": 140,
     "parentId": "<zone-2-column-cell-id>"
   }
   ```
3. Call `import-diagram` with `mode: "add"` and the returned XML.

---

### "Move all three diagram types into the editor as pages"

1. Call `POST http://localhost:8787/api/drawio-mcp-all-pages`:
   ```json
   { "architecturePath": "inputs/projects/<customer>/<project>/architecture.json" }
   ```
   This generates context, logical, and deployment diagrams and imports them as
   three named pages: **Context**, **Logical Architecture**, **Deployment**.

## Finding Parent Cell IDs

When asked to place a node inside a specific container, use `list-paged-model` with a filter
to narrow results. Look for cells where:
- `value` matches the container name (e.g. `"Management"`, `"zone-1"`, `"prod-vpc"`)
- `style` contains `container=1` (for location containers)
- The cell is a child of the expected parent

The outer `id` of that container cell is your `parentId` for the snippet API call.

---

## Architecture JSON Reference Path

When using the snippet or multi-page APIs, `architecturePath` is relative to the repo root.
For named projects it is:

```
inputs/projects/<customer-slug>/<project-slug>/architecture.json
```

For the legacy workspace it is:

```
inputs/uploads/current/architecture.json
```

The current `architecturePath` is shown in the Network Picasso workbench header after a
successful intake run.
